# ALLinSSL 群晖证书部署插件

[ALLinSSL](https://github.com/allinssl/allinssl) 的模块插件。启用后，工作流中会多出一个 **「部署到群晖」** 节点，把申请或上传的 SSL 证书自动导入群晖设备的证书管理。

- 支持群晖 NAS（DSM）和群晖路由器（SRM），两者使用同一套接口
- 同一张证书不会重复上传；设备上的旧记录过期后自动覆盖
- 可选择将证书设为设备的默认证书

## 环境要求

| 项目 | 要求 |
| --- | --- |
| ALLinSSL | v1.1.4 及以上（带「插件管理」页面的版本） |
| 运行平台 | Linux amd64 / arm64 |
| 群晖账号 | 属于管理员组，且 **未开启两步验证** |
| 构建（可选） | Go 1.25 及以上、make |

> 本仓库 1.x 版本是旧式的「部署插件」（单个可执行文件 `synology_dsm` / `synology_srm`）。2.0.0 起改为模块插件，两者安装和使用方式不同，迁移方法见 [从 1.x 迁移](#从-1x-迁移)。

## 安装

### 1. 获取插件目录

在本仓库根目录执行：

```bash
make package
```

会在 `dist/` 下生成各平台的发布包：

```text
dist/synology_2.0.0_linux_amd64.tar.gz
dist/synology_2.0.0_linux_arm64.tar.gz
```

只需要当前机器架构的版本时，执行 `make build`，直接得到 `dist/synology/` 目录。

### 2. 放入 ALLinSSL 插件目录

把与服务器架构对应的包解压到 ALLinSSL 的插件目录（默认是 ALLinSSL 运行目录下的 `plugins`）：

```bash
tar -xzf synology_2.0.0_linux_amd64.tar.gz -C /path/to/allinssl/plugins/
```

解压后的结构必须如下，**目录名必须是 `synology`**，不能改名：

```text
plugins/
└── synology/
    ├── plugin.json          # 插件清单
    ├── bin/synology         # 后端程序
    └── frontend/index.js    # 节点配置表单
```

### 3. 启用插件

1. 登录 ALLinSSL，打开 **插件管理**
2. 找到「群晖证书部署」，点击 **启用**，运行状态应变为「运行中」
3. 按提示 **刷新页面**，工作流中才会出现新节点

## 使用

1. 打开 **自动化部署**，新建或编辑一个工作流
2. 先添加 **申请证书**（或 **上传证书**）节点
3. 在其后点击加号，选择 **部署到群晖**
4. 点击该节点，填写配置并保存：

| 配置项 | 说明 |
| --- | --- |
| 证书来源 | 使用哪个节点产出的证书，默认选中最近的申请/上传节点 |
| 设备地址 | 包含协议和端口，例如 `https://192.168.1.2:5001`。DSM 默认 HTTPS 端口 5001，SRM 默认 8001 |
| 用户名 | 群晖管理员账号 |
| 密码 | 该账号的密码 |
| 设为默认证书 | 开启后，导入的证书会成为设备的默认证书。默认关闭 |
| 跳过证书校验 | 不校验设备自身的 HTTPS 证书。设备使用自签名证书或通过 IP 访问时需要开启。默认开启 |

5. 保存工作流并执行

需要部署到多台设备时，添加多个「部署到群晖」节点即可。

### 部署行为

- 导入的证书在群晖中的描述为 `allinssl-` 加证书指纹前 6 位，例如 `allinssl-3fa9c1`，插件据此识别自己上传过的证书
- 设备上已有同一张证书且未过期：跳过，不重复上传
- 设备上的同名记录已过期：按原记录覆盖
- 证书本身不在有效期内：直接报错，不上传

### 注意事项

- 节点配置（包括密码）随工作流保存在 ALLinSSL 的数据库中，建议为部署单独建立一个群晖管理员账号
- 部署失败时，工作流日志里只会显示「执行失败」；具体原因在 ALLinSSL 进程的输出中，可查找 `执行工作流失败` 或 `[synology]` 开头的行

## 升级

1. 在 **插件管理** 中 **停用** 插件
2. 用新版本覆盖 `plugins/synology/` 目录
3. 重新 **启用** 并刷新页面

`plugin.json` 发生变化（例如版本号）时必须先停用再启用，直接重启会提示「模块清单已变化」。已保存的工作流节点配置不受影响。

## 从 1.x 迁移

1. 按上面的步骤安装并启用 2.0.0
2. 在工作流中，把原来「部署」节点里选择 `synology_dsm` / `synology_srm` 插件的那一步，换成新的「部署到群晖」节点，并重新填写设备地址、用户名和密码
3. 确认新节点工作正常后，删除插件目录下旧的 `synology_dsm`、`synology_srm` 可执行文件，以及授权 API 管理中对应的旧授权

## 常见问题

**插件管理里看不到插件**
检查目录结构是否为 `plugins/synology/plugin.json`，以及目录名是否为 `synology`。

**运行状态为「清单无效」或「运行异常」**
查看「最近错误」一列。常见原因：`bin/synology` 没有执行权限（执行 `chmod +x plugins/synology/bin/synology`），或下载了与服务器架构不符的包。

**启用后工作流里没有「部署到群晖」节点**
启用或停用插件后需要刷新页面。

**工作流执行失败，但日志里看不到原因**
在 ALLinSSL 进程的输出中查找 `[synology]` 开头的行，其中有完整的失败原因。

**登录失败（错误码 400 / 403）**
400 为用户名或密码错误；403 表示账号开启了两步验证，请改用未开启两步验证的管理员账号。

**提示「没有可部署的证书」**
节点之前没有申请证书或上传证书节点，或「证书来源」未选择。

**提示 x509 / certificate 相关错误**
设备使用自签名证书，请开启「跳过证书校验」。

## 开发

```text
cmd/synology/        后端程序入口
internal/module/     ALLinSSL 模块协议（协议 1）的插件端实现
internal/workflow/   「部署到群晖」节点：读取节点配置和证书
internal/synology/   群晖 Web API 客户端与证书导入
internal/certutil/   证书解析工具
internal/testcert/   测试用自签名证书
package/             随插件发布的清单和前端入口
```

```bash
make help      # 显示可用命令
make build     # 生成 dist/synology（当前系统和架构）
make package   # 生成各平台发布包
make test      # 运行单元测试
make vet       # 静态检查
make fmt       # 格式化代码
```

发布新版本时，修改 `package/plugin.json` 中的 `version`，构建时会自动写入后端程序。

### 工作原理

ALLinSSL 启动 `bin/synology` 并通过环境变量下发凭据；后端程序监听本机回环端口，把地址写到标准输出。之后：

- ALLinSSL 请求 `GET /api/workflow`，得到插件注册的节点 `deploy`，在工作流中对应节点类型 `plugin:synology:deploy`
- 工作流执行到该节点时，ALLinSSL 请求 `POST /invoke`，把节点配置和证书交给插件，插件调用群晖 Web API 完成导入
- 前端入口 `frontend/index.js` 向工作流编辑器注册节点的标题、摘要和配置表单
